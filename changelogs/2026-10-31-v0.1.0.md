# v0.1.0 — 2026-10-31

项目立项，完成阶段 1 的显示/按键脚手架和 ESP-SDR 接入方案。

## 背景

你看到的新闻是 ESP-SDR（ESPARGOS）：

- 用未公开的 debug 通路让 CPU 直接读 WiFi 接收机的 raw I/Q；
- 支持 ESP32-S3，80/40/16 MS/s，片内 256~2048 bin FFT；
- 上游把 I/Q/频谱送到电脑，不支持和 ST7735 这样的板载屏；
- 上游 issue #7 正在要“ESP32 自己显示瀑布图”；
- 社区 fork 已在 ESP32-S2 TFT Feather（ST7789）上做到板载频谱/瀑布。

结论：**不是 ST7735 硬件不支持，是上游没做显示。**

## 本版本完成

### 硬件方案

- ESP32-S3-DevKitC-1，16MB flash，无 PSRAM
- ST7735S 128x160 SPI，3.3V
- 4 按键：GPIO4/5/6/14
- 屏幕：SCK12 / MOSI11 / CS10 / DC9 / RST8 / BL7
- 横屏偏移 `(4,0)`

### 阶段 1 显示 demo

- ESP-IDF 工程，`main/main.c`
- `esp_lcd` + `waveshare/esp_lcd_st7735`
- 160x128 RGB565 帧缓冲，40KB 内部 RAM
- 颜色条 / 渐变 / 移动块三种画面
- K3 切模式，K4 回到颜色条
- 用于验证 SPI、偏移、方向、背光和按键
- 已在 ESP-IDF v5.4.2 / esp32s3 上编译并实机验证
- 实机结果：屏幕无偏移/变形，K1~K4 全部正常
- 本机 ESP-IDF 驱动使用 `set_gap(0,0)`

### ESP-SDR 接入方案

`docs/esp-sdr-integration.md` 记录了：

- 把 S3 `capture()` 拆成 `acquire_iq()` + 发送；
- 用 `spectrum_snapshot()` + `s3_spectrum_acquire()` 做片内 FFT；
- S3 的 80/40/16 MS/s 与 `spectrum.c` rate 表对齐；
- 显示任务与串口 RF 命令的互斥；
- 160x128 频谱/瀑布、按键调谐；
- 内存/时序预算和验证顺序。

## 限制

- 跑 SDR 时不能同时做 RID；
- S3 主要覆盖 2.4GHz 附近，5GHz 要 C5；
- raw I/Q 机制未公开，部分上游代码 AI 生成；
- 增益/功率未校准，显示相对强度；
- 无 PSRAM，帧缓冲/瀑布要省内存；
- GPL-3.0，和 Apache-2.0 的 RID 扫描器分开。
